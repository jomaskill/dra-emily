<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| repository observations → human evidence | Deterministic facts cross into records controlled by clinical, legal, media, operations, and privacy reviewers. |
| repository filesystem → command output | Local files are scanned and summarized without exposing secrets or sensitive evidence. |

## STRIDE Threat Register — ASVS L1

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-01-01 | Tampering | Release-item identity and status | high | mitigate | Join only on stable ID + exact hash + locale + route/context; reject duplicates, stale identities, and unknown statuses in `GovernanceEvidence`. |
| T-01-02 | Information Disclosure | Filesystem scan and diagnostics | high | mitigate | Allow-list roots, reject symlinks/forbidden paths, and print IDs/reasons rather than content or evidence payloads. |
| T-01-03 | Spoofing | Human approval status | high | mitigate | Keep decisions outside generated/config data and require explicit named human evidence fields; automation has no approval writer. |
| T-01-04 | Denial of Service | Concurrent canonical writes | medium | mitigate | Use bounded explicit roots, deterministic traversal, exclusive locks, temporary files, and atomic rename. |
| T-01-05 | Repudiation | Generated run provenance | medium | mitigate | Record timestamp, commit SHA, dirty-tree state, command version, and target path in the run envelope. |
</threat_model>
